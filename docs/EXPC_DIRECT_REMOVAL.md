# Штатное удаление без предварительных окон EXPC — 2026-10-08

STATUS: реализация, сборка и фоновые проверки завершены. Визуальная приёмка NOT TESTED.
Основа: 0aca600c, ветка expc/updates-vault. Этот сценарий заменяет EXPC_UNIFIED_OPERATION.md для штатного удаления.

## Изменения

- Кнопка панели вызывает RunSelected(0); верхнее и контекстное меню используют общий ActionItem → RunSelected. В ActionUi.cs штатная команда теперь идёт в StandardRemoval, минуя OpenOperation. Конструктор OperationWindow явно запрещает action=0.
- До завершения внешнего деинсталлятора нет собственной формы подтверждения, ожидания, журнала или результата. Статус и ошибки запуска выводятся в главном окне; полный текст доступен в подсказке. Защита повторного запуска — блокировка команд и атомарный guard StandardRemoval.
- Только подтверждённый результат removed без требования перезагрузки разрешает адресный поиск Win32. Отмена, ошибка, неизвестный результат и Store не запускают этот поиск. При пустом результате — только строка состояния. При найденных остатках открывается один OperationWindow, сразу с выбором остатков.
- Штатные окна деинсталлятора и UAC остаются. Автоматических ответов, новых тихих флагов, принудительного завершения процессов и автоматической перезагрузки нет. ProductActions и ожидание дочерних процессов сохранены.
- Принудительное удаление и удаление только записи по-прежнему требуют подтверждения. Они не входят в штатный маршрут.
- Окно остатков: название/иконка, шрифт 10,5 вместо 9 pt, раскрываемые секции, точные пути, выбор элементов/секций и частичное состояние. Размещение рассчитывается относительно главного окна на его мониторе, с учётом DPI и рабочей области.
- Все объекты изначально не отмечены. Распознанные профили/настройки и консервативно все найденные ключи реестра относятся к пользовательским данным. Поэтому секция «Реестр» может быть пустой; это не означает отсутствия ключей в «Пользовательских данных». Поиск ограничен прежними доказанными кандидатами BCU, общий обход пользовательских каталогов не добавлен.
- CleanupPlan исключает выбранного предка неотмеченного объекта. Файлы удаляются поштучно, каталоги — только нерекурсивно: неотмеченный либо новый вложенный объект не удаляется через родителя. Перед каждой операцией повторяется проверка исходного кандидата BCU.
- Реестр резервируется перед удалением. Для выбранных остатков используется DeleteSubKey, который отказывается удалять ключ с дочерними ключами. Рекурсивный elevated reg.exe здесь не используется; недоступный без повышения ключ остаётся с ошибкой в журнале. Удаление только uninstall-записи сохраняет прежний механизм.
- Подтверждение очистки, выполнение и результат находятся в том же окне. Журнал изначально свёрнут; над ним одна строка «Подробности / Журнал», «Очистить», «Копировать», «Сохранить как…». Очистка видимого текста не изменяет operations.jsonl и резервные копии. Диалог сохранения файла открывается только по явной команде пользователя.
