## Изменение сценария

Раньше RunSelected открывал подтверждение, OperationWindow ожидания, сообщение результата, ещё одно подтверждение и JunkWindow. Теперь обычное/принудительное удаление, адресный поиск и удаление только записи используют один OperationWindow:

1. Название, копия иконки из кэша списка (универсальная при отсутствии), описание, «Удалить»/«Отмена». Для отдельного поиска — «Найти остатки».
2. Подтверждение сменяется статусом ожидания и индикатором. Подробности/журнал изначально свёрнуты, раскрываются здесь же.
3. Результат/ошибка внутри диалога. Подтверждённое удаление Win32 без перезагрузки позволяет явно запустить адресный поиск.
4. Таблица остатков в этом же диалоге, без отмеченных по умолчанию строк. «Удалить выбранное» переводит в состояние подтверждения здесь же. «Отмена» возвращает таблицу. Подтверждение вызывает прежний адаптер с повторной проверкой принадлежности и резервированием реестра. Не удалённые объекты остаются в таблице, ошибки — в статусе и журнале.

Отдельные собственные окна ожидания, результата, остатков и дополнительные MessageBox в этом маршруте убраны. MainWindow хранит один экземпляр операции; повторная команда не создаёт другой. При Running диалог не активируется повторно. Advance игнорирует повторный запуск, включая время обновления списка. Amber, геометрия главного окна, RU/EN и текущие обновления сохранены.

## Внешние окна и отмена

- Штатный деинсталлятор приложения, включая деинсталлятор самого BCU, и UAC могут показывать свои подтверждения. EXPC не нажимает в них «Да», не добавляет тихие параметры и не обещает скрыть их.
- Во время ожидания нет вызовов Activate/ShowDialog/TopMost из операции. Реальное распределение фокуса с конкретными установщиками не проверялось.
- «Отмена» до запуска закрывает диалог без вызова backend. Возвращённая деинсталлятором отмена 1602 и отказ UAC 1223 сохраняются отдельными исходами.
- «Прекратить ожидание» отменяет только наблюдение: observation-stopped не считается успехом. Поиск остатков недоступен в этой операции даже при одновременно пришедшем успешном результате. Установщик не завершается принудительно.
- Для Store AsTask().WaitAsync(token) теперь прекращает ожидание EXPC без передачи отмены операции Windows.
- ProcessFamily, проверка исчезновения регистрации и доступности наблюдения дочерних процессов сохранены. Классификация кодов выхода вынесена в Completion без изменения условий успеха. Автоматической перезагрузки нет.
