## Группы и штатное удаление

`ProgramGroups` строит отдельные строки представления. Совпадающие названия группируются только при нескольких записях; Microsoft Visual C++ Redistributable образует семейство с исходными поколениями, версиями и архитектурами внутри. Название группы содержит количество подходящих записей. Дочерняя строка хранит исходный AppEntry без объединения регистраций/команд. Оригинальная иконка и версия остаются; tooltip содержит издателя, путь, команду и источник регистрации.

Плюс слева переключает группу. Двойной щелчок по заголовку переключает раскрытие, но не запускает удаление; по конкретной записи вызывает тот же `RunSelected(0)`, что пункт «Штатное удаление» (жирный). Для группы SelectedEntry=null, действия над программой отключены. Существующее подтверждение с Cancel по умолчанию и блокировка повторного запуска сохранены.

Поиск показывает подходящих детей и временно раскрывает группы; после очистки поиска возвращается сохранённое состояние. Сортировка упорядочивает группы по первому соответствующему дочернему элементу выбранной колонки, детей — по той же колонке. Раскрытие сохраняется в settings, при сортировке, обновлении и последующем запуске. Реестр не изменяется; устаревшие/ненужные записи не определяются.

## Нативное окно .NET

При подтверждённом совместимом runtime launcher сразу переходит к приложению без окна установки и обращения к сети для зависимости. Иначе открывается Win32-окно RU/EN без .NET: два независимых квадратных checkbox справа, взаимоисключающий выбор, изначально оба сняты. OK доступна без выбора; этот случай выдаёт предупреждение и завершает launcher без запуска EXPC. Escape/Отмена закрывают окно.

Строка runtime, строка Microsoft и только слово WinGet выделены жирным #339CFF. Microsoft открывает [официальную страницу Desktop Runtime 10.0.12 Windows x64](https://dotnet.microsoft.com/en-us/download/dotnet/thank-you/runtime-desktop-10.0.12-windows-x64-installer), а не общий список SDK; есть «Проверить установку». Страница проверена по Microsoft в этом задании.

WinGet используется напрямую: `install --id Microsoft.DotNet.DesktopRuntime.10 --exact --source winget --architecture x64`. ID соответствует [документации Microsoft](https://learn.microsoft.com/en-us/dotnet/core/install/windows). Без UniGet UI, SDK, ASP.NET или установки других менеджеров. Состояние и неопределённая полоса в том же окне; проценты не выдумываются. Message-loop timer опрашивает процесс без блокирующего ожидания UI. Нет автоматического подтверждения UAC. Отсутствие WinGet/ошибка показывают причину и позволяют выбрать Microsoft.

Успех определяется повторной проверкой runtime, не одним exit code. Зелёная галочка/«Готово» и OK — запуск ровно один раз. Коды перезагрузки объясняются; перезагрузка автоматически не выполняется. Таймаут 15 минут прекращает наблюдение, не завершает установщик. Повторный запуск при ещё работающем процессе запрещён. «Прекратить ожидание» закрывает launcher без завершения установщика и без запуска EXPC.

Физический вид и реальное поведение WinGet/UAC этой формы не проверены на рабочем столе пользователя; фоновые проверки покрывают модель выбора/состояний и сборку.

## PDF-XChange: доказанные причины и границы вывода

**ImageList:** до исправления скрытый STA-тест создания нативного TreeView воспроизвёл `ArgumentException: Parameter is not valid` с `Image.get_Size → ImageList.CreateBitmap/CreateHandle → TreeView.OnHandleCreated`. `using var Bitmap` освобождал картинки галочек сразу после Images.Add, до ленивого создания native handle. Теперь исходные bitmap принадлежат форме и живут до освобождения TreeView/ImageList; потока изображения нет. Декоративная иконка отделяется копированием, повреждённая не блокирует форму.

Дополнительный стресс-тест выявил повторный вход CustomDraw при замене StateImageList: WinForms заново добавлял native nodes до завершения связей managed/native. Замена теперь внутри BeginUpdate/EndUpdate, без подавления исключения. Сначала освобождается дерево, затем ImageList и bitmap. Проверены повторное открытие, явное пересоздание handle, 20 циклов, смена BackColor, bitmap 96/144 DPI, снятая/отмеченная/частичная секция. Это проверка реальных скрытых WinForms-контролов, не только модели очистки; визуальный DPI отдельно NOT TESTED.

**Пути:** прежний `Find` немедленно бросал CleanupScopeUnknown при неуспешном SafeDirectory по InstallLocation. Это отдельная причина отказа адресной проверки, не следствие ImageList. Теперь до запуска сохраняются исходные Sources (scope/view/key), Metadata (включая ProductCode/команду/DisplayIcon), IconPath, подтверждённые пути установки и связанные данные. Исходный пустой InstallLocation не переписывается догадкой. Дополнительные корни выводятся только из зарегистрированных DisplayIcon/команды, проходят прежние проверки принадлежности, product-specific leaf, общих корней и соседних установок. MSI требует согласованных ProductCode/команды/Icon. Проверка после удаления использует snapshot и повторно проверяет границы.

Отсутствующий InstallLocation больше не обрывает все проверки. Успешные адресные участки сохраняются при ошибке другого; исключение доступа не приравнивается к отсутствию папки. Полный пустой результат, найденное, частичное выполнение и ошибка без выполненной проверки различаются. Частичный результат содержит находки и причину ограничения, не получает зелёный check; предупреждение остаётся после очистки. Пользовательские данные не отмечаются автоматически; исключённые потомки, новые объекты, границы реестра, резервирование и корзина сохранены.

Ноутбучного snapshot/журнала PDF-XChange с реальными путями нет. Поэтому не установлено, какие именно дополнительные источники у той установки были доступны и пройдут ли они проверку принадлежности. **Случай PDF-XChange целиком NOT TESTED**; подтвердили и исправили воспроизводимое исключение и общий ранний отказ при пустом InstallLocation, а не объявили конкретную установку полностью исправленной.

Кнопки журнала RU/EN теперь явно «Очистить журнал», «Скопировать журнал», «Сохранить журнал…». Они не удаляют резервные копии. «Удалить выбранное» отдельно и доступно только при допустимом выборе.
