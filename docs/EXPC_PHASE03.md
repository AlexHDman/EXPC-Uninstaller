# EXPC-Uninstaller — Phase 03

Дата: 2026-10-07 (Europe/Moscow). Основа f9341d968ba852cd824fecfe2fde2f80a90ef4b1, ветка expc/phase-03. Пользователь подтвердил работу portable .NET 10 и вкладок Phase 02A.

## STATUS

Подключены действия одной выбранной записи без изменения главной компоновки EXPC-002. На рабочем компьютере программы, остатки и uninstall-записи не удалялись. ## Реализация

- Кнопка корзины, меню Действия и контекстное меню: штатное удаление, принудительный адресный поиск, поиск остатков, удаление только записи, папка, реестр, официальный сайт, Google. Доступность зависит от записи/защиты/наличия метаданных. Нет массового удаления.
- Быстрый registry reader дополнен метаданными действий и списком всех точных hive/view/key после дедупликации; глубокого pipeline, Win32_Product, сети и обхода каталогов на старте нет. Исходная версия/издатель/путь/команда/защитные флаги повторно проверяются перед действием.
- Для EXE путь отделён от аргументов, параметры сохраняются без интерпретации командной оболочкой. Поддержаны кавычки, пробелы и переменные окружения. Относительные/сетевые команды, shell/script/rundll32 и неизвестные формы отклоняются с объяснением. MSI /I ProductCode преобразуется в /x, добавлены /norestart и REBOOT=ReallySuppress; ProductCode сопоставляется с MSI-регистрацией. MSI по пути .msi, patch/repair-команды сейчас не поддержаны.
- Оболочка asInvoker. Повышение EXE применяется при ERROR_ELEVATION_REQUIRED; manifest самого установщика также может запросить UAC. При UAC cancel — отмена. Нет автоматического reboot и принудительного завершения деинсталляторов.
- Наблюдение процессов включается только на действие: события Win32_ProcessStartTrace плюс Toolhelp-снимки потомков; после завершения отдельно проверяется отсутствие регистрации. Код 1602 — отмена, 3010/1641 — необходимость перезагрузки; другие ненулевые коды — ошибка. Нулевой код при оставшейся записи — «не подтверждено». Если WMI-наблюдение недоступно, успех не объявляется. Прекращение ожидания не убивает внешние процессы.
- Адаптер остатков — узкая адаптация BCU JunkCreatorBase/UninstallerLocationScanner/RegistryKeyJunk, с сохранённым copyright. Используются существующие KlocTools ProcessStartCommand и PathTools; Store остаётся на штатном PackageManager, как в BCU AppManager. Общий UninstallTools/JunkManager и мастера не подключены.
- Кандидат папки требует явных InstallLocation и EXE внутри неё, отдельного имени продукта и отсутствия пересечений с другими регистрациями/EXE/иконками. Общие корни, каталоги производителя/компонентов, Windows, WindowsApps, неоднозначные пути и reparse points исключаются. Обход разрешён только внутри этого адресного корня и ограничен числом объектов. Если полный быстрый список прочитан с ошибками, зачистка блокируется.
- Кандидат реестра: только точный SOFTWARE/издатель/продукт с совпадающим InstallLocation, без вложенных ключей. Совпадение лишь по имени недостаточно. Перед каждым удалением принадлежность проверяется снова. Все checkbox изначально сняты; требуется отдельное подтверждение. Удаление файлов без корзины явно обозначено.
- Перед удалением ключа reg.exe соответствующей архитектуры экспортирует .reg; при ошибке backup удаления нет. Рядом записана инструкция восстановления с /reg:32 или /reg:64. Только удаление уже подтверждённого HKLM-ключа может повториться с runas после отказа доступа. Журнал намерений/результатов и backup — local-data рядом с EXE. Принудительный поиск не выдаёт снятие регистрации за полное удаление.
- Store: только текущий пользователь; системные подписи, framework/resource и зависимости других пакетов отсекаются до вызова. Windows сама запрещает non-removable packages, force-обхода нет. Эвристическая Win32-зачистка для Store недоступна.

## Ограничения / NOT TESTED

- Реальное удаление Microsoft Store приложения, отдельные UAC/standard-user/elevation сценарии, HKLM backup/delete с повышением и x86 view restore — NOT TESTED. Отдельные пути Store и UAC подключены, но не аттестованы реальным тестом удаления.
- 150% DPI, другие архитектуры, Windows 10 и старые ПК — NOT TESTED в этой фазе. Работающий shell макет не изменён.
- Нет широкого поиска AppData, служб, задач, COM, драйверов, общих компонентов и совпадений по названию. Для MSI без явного EXE в InstallLocation файловых кандидатов может не быть. Это намеренное ограничение границ, отсутствие кандидатов не объявляется полной чистотой.
- Защищённые или занятые файлы возвращают ошибку; обход ACL, захват владения, планирование удаления при reboot не реализованы. Произвольные EXE могут иметь собственные правила reboot/cancel; EXPC сам reboot не инициирует.
- Detached/elevated broker/service не всегда полностью наблюдаем; проверка регистрации — дополнительный факт, не доказательство удаления всех файлов. При неоднозначности нельзя заявлять полный успех.
- Registry Editor, уже открытый пользователем, может сохранить прежний ключ: EXPC не завершает чужой regedit. Открытие сайта/Google передаёт выбранный запрос только по явному действию пользователя; эти внешние переходы LIVE не выполнялись.

## Воспроизведение

Сборка/тесты: команды Phase 02A с текущими исходниками. Упаковка в новый каталог:

~~~console
dotnet msbuild scripts/Build-ExpcPortable.proj -t:Package -p:OutputRoot=C:/AI/EXPC-Uninstaller/artifacts/phase03/verified
dotnet msbuild scripts/Build-ExpcPortable.proj -t:Extract -p:OutputRoot=C:/AI/EXPC-Uninstaller/artifacts/phase03/verified
~~~

Для повторного выполнения нужен другой пустой OutputRoot. Sandbox harness имеет проверку WDAGUtilityAccount + отдельный sentinel C:/EXPC-Test/ALLOW-SANDBOX-TESTS; на host отказывает до fixture-записей. Run-Phase03-Sandbox.cmd, Verify-Phase03-Sandbox.cmd, Run-Phase03-Msi.cmd и Collect-Phase03-Sandbox.cmd предназначены только для Sandbox с read-only payload/scripts и отдельной writable папкой результатов.

Справочники: [MSI options](https://learn.microsoft.com/en-us/windows/win32/msi/standard-installer-command-line-options), [current-user RemovePackageAsync](https://learn.microsoft.com/en-us/uwp/api/windows.management.deployment.packagemanager.removepackageasync).
